## Why CORS exists

Browsers enforce the **same-origin policy**: a page served from `a.com` cannot read
responses from `b.com` unless `b.com` explicitly allows it. CORS (Cross-Origin
Resource Sharing) is the mechanism servers use to opt in.

```js
// Express example: allow a specific origin
app.use((req, res, next) => {
  res.setHeader("Access-Control-Allow-Origin", "https://myapp.com");
  res.setHeader("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE");
  res.setHeader("Access-Control-Allow-Headers", "Content-Type,Authorization");
  next();
});
console.log("Hello")
```

## Preflight requests

For "non-simple" requests (custom headers, methods like `PUT`/`DELETE`, or
`Content-Type: application/json`), the browser sends an `OPTIONS` request first.

```
OPTIONS /api/users HTTP/1.1
Origin: https://myapp.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: content-type
```

The server must respond with matching `Access-Control-Allow-*` headers or the
browser blocks the real request before it's ever sent.

## Common mistakes

1. Setting `Access-Control-Allow-Origin: *` while also trying to send credentials
   (cookies) — browsers reject this combination.
2. Forgetting to handle the `OPTIONS` method on your router.
3. Confusing a CORS error in devtools with a server-side 500 — the request often
   never reaches your handler.

CORS is a browser-enforced rule, not a network-level restriction — server-to-server
requests (curl, another backend) are never blocked by it.
